# WORKFLOW.md — 세션 운영 규칙 (Z.ai GLM Coding Plan 토큰 절약)

Z.ai GLM Coding Plan은 5시간 단위 할당량(Quota)·토큰 한도로 작동한다.
핵심은 **요청마다 재전송되는 컨텍스트(대화 누적 + 첨부 파일)를 최소화**하는 것이다.

---

## 1. 세션 수명 주기

```
[단계 착수]  새 세션 → "summary.md + PLAN.md 해당 단계만 읽고 시작"
             → 구현 계획 3단계 요약(Plan Mode) → 사용자 승인 → 코드 작성
[세션 종료]  summary.md 갱신 → /clear   (세션 내 대화가 길어지면 /compact)
[단계 종료]  §3 자동 프로토콜 수행
```

- 기능 구현이 끝나거나 작업 주제가 바뀌면 **반드시 세션 초기화(/clear)** —
  대화가 길수록 이전 메시지 전체가 매 요청마다 재전송되어 토큰 소모가 급증한다.

## 2. 세션 시작 프롬프트 템플릿 (복사해서 사용)

```text
summary.md와 .agent/PLAN.md의 S(n) 항목만 읽고 시작하세요.
먼저 구현 계획을 3단계로 요약만 해주세요. 승인 후 코드를 작성하세요.
수정 대상은 다음 파일뿐입니다: <PLAN.md 해당 단계의 핀포인트 목록>
```

## 3. 단계 종료 자동 프로토콜 (에이전트 의무 — 매 단계/세션 완료 시)

에이전트는 완료 판정 즉시, 사용자가 요청하지 않아도 자동 수행한다:

1. **summary.md 갱신** — 완료/미완료 항목, 결정·변경 사항, 다음 세션 정보(§5 템플릿)
2. **검증** — 해당 단계 완료 기준(PLAN.md) + lint/typecheck/test
3. **git commit + push** — `CLOUD.md` §1 원칙(종료 전 push)
4. **다음 단계 안내 제공** — 사용자에게 ①`/clear` 권장 ②다음 세션 시작 프롬프트(§2 양식, 복사 가능) 전달

→ 사용자는 새 세션에서 프롬프트를 붙여넣기만 하면 다음 단계가 착수된다.

## 4. 세션 중 토큰 절약 체크리스트

- [ ] "전체 프로젝트 봐줘" 금지 — PLAN.md의 **핀포인트 파일만** 지정·수정
- [ ] 에러 로그는 **핵심 메시지 + 스택 상단 20~30줄**만 전달 (수천 줄 트레이스 붙여넣기 금지)
- [ ] 코딩 스타일·룰을 프롬프트로 반복 입력 금지 — `CLAUDE.md`·`.agent/` 문서가 이미 담당
- [ ] 대용량 파일(.psd/.png/로그)은 **경로로만** 참조, AI에게 첨부 금지
- [ ] 긴 대화: `/compact` / 단계·주제 전환: `/clear`
- [ ] 연동 도구(OpenCode·Roo Code·Cline 등)의 **Z.ai 컨텍스트 캐싱 활성화** 확인 —
      반복 시스템 프롬프트·프로젝트 규칙의 재전송 비용 절감 (Z.ai 파이프라인 지원)
